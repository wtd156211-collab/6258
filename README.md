# 调色板量化（从 0 实现）

仓库里只有这份说明、`samples/**` 与 `.gitignore`，没有实现代码，实现要新写。

交付形态：仓库根目录的 `palettecut/` 包（Python 3.13 标准库，库 + `python -m palettecut`
命令行入口）、用样例跑出来的 `web/` 下对比页面、`tests/`（`unittest`）。

## 一、范围

要做：读未压缩位图，按给定的颜色数上限挑出一组代表色，把每个像素映射过去，产出调色板与
索引图，统计两种误差，再生成一份并排对比页面。

明确不做：不实现图片解码（只吃第四节规定的未压缩格式，PNG/JPEG 一律不认）；不做抖动与
误差扩散（每个像素独立映射）；不做缩放、裁剪、旋转、透明通道与色彩空间转换（一律按 8 位
sRGB 数值直接算）；不做批量目录、不做增量缓存、不联网、不引第三方依赖、不加构建步骤。

## 二、口径与公式

原图像素写作 `(r, g, b)`，调色板第 `i` 条写作 `(R, G, B)`，都是 0–255 的整数。

- 距离口径：比较颜色用平方欧氏距离 `d = (r-R)² + (g-G)² + (b-B)²`，两条一样近取索引小的。
- 索引图是原图的逐像素映射：每个像素独立落到调色板里的一条颜色上，不做抖动与误差扩散；落
  哪一条由实现决定，一般就取距离最小的那条。
- 单像素误差 `e = max(|r-R|, |g-G|, |b-B|)`。
- 整体平均误差 `mean_abs_error = Σ(|r-R| + |g-G| + |b-B|) / (3 × 像素数)`，即逐通道平均绝对
  误差，保留 3 位小数（四舍五入）。
- 单像素最坏误差 `max_pixel_error = max(e)`，整数。
- 两个口径都按「原图像素」与「该像素索引指向的调色板颜色」之差算，所以映射得越近，两个误差
  越好达标。
- 颜色数上限 `K` 是硬上界：调色板条目数不得大于 `K`，且每条至少被一个像素用到，不许留占位色。
- 原图的不同颜色数不超过 `K` 时必须无损：调色板就是这些颜色本身，两种误差都是 0。

## 三、数据结构与处理流程

内存里固定下来的只有两样：调色板（不超过 `K` 条 0–255 的 RGB）和索引图（与输入同宽高、
每像素 1 字节）。其余结构自由，但规模要可控：几百万像素的图不能一边算一边把逐像素颜色
统计复制好几份，预算见第五节。

流程不限：读头 → 一遍扫描取统计 → 选代表色 → 一遍扫描映射并累计误差 → 写文件。确定性要求
会同时卡住初始化方式和遍历顺序。

## 四、输入输出与文件格式

输入 `samples/images/*.ppm`：二进制 PPM（P6），规范形式固定为 `P6\n<宽> <高>\n255\n`，紧接着
`宽 × 高 × 3` 字节，RGB 行优先、无注释、无填充，最大值只认 255；样例都是这个形式，别的变体
不需要支持，遇到按输入不可用处理。

命令都在仓库根目录跑：

- `python -m palettecut quantize <输入.ppm> <颜色上限> --out <输出目录>`：颜色上限取 1–256 的
  整数，输出目录不存在就建。
- `python -m palettecut page --ppm <输入.ppm> --dir <输出目录> --html <页面文件>`：用上一步的
  输出生成对比页面。
- 退出码 `0` 成功、`1` 输入不可用（文件缺失、头不合法、目录里缺输出）、`2` 用法错误；非 0 时
  不写半成品。

`quantize` 写三个文件，并把一行汇总打到标准输出，除这一行外不要再打别的：

1. `palette.txt`：ASCII、LF、末行有换行；第一行是条目数，随后每行 `r g b`（十进制、单空格
   分隔、0–255）；条目按 `(r, g, b)` 字典序升序排列。
2. `indices.pgm`：二进制 PGM（P5），头 `P5\n<宽> <高>\n255\n`，随后每像素 1 字节索引，行优先；
   索引 `i` 指向 `palette.txt` 的第 `i+1` 条。
3. `report.json`：UTF-8、LF、末行有换行；键固定为 `image`（只写文件基本名）、`width`、`height`、
   `pixels`、`colors_limit`、`colors_used`、`mean_abs_error`（3 位小数）、`max_pixel_error`、
   `elapsed_ms`（非负整数）。
4. stdout：`colors_used=<n> mean_abs_error=<x.xxx> max_pixel_error=<n> elapsed_ms=<n>`，单空格分隔。

`page` 写一个自包含页面：UTF-8 单文件，双击可开（`file://`），不引外部资源、不联网、不构建；
左右并排画原图与量化结果（Canvas，两张画布分别带 `id="original"` 与 `id="quantized"`），下面给出
颜色数、`mean_abs_error`、`max_pixel_error` 与耗时，四个节点分别带 `data-metric="colors"`、
`"mean_abs_error"`、`"max_pixel_error"`、`"elapsed_ms"`。页面画出来的量化图和显示的数字只能来自
`palette.txt`、`indices.pgm`、`report.json`，不许在页面里重新选色或重算误差。

## 五、性能与验收口径

单进程、单线程、只用标准库；本机 WSL 的 `python3`，冷启动计入。`samples/images/mixed.ppm`
（1920×1080，2,073,600 像素，颜色上限 256）单次 `quantize` ≤ 8 s，峰值常驻内存 ≤ 384 MB
（由验收方在进程外测），其余样例在 1 s 量级。

逐条核对：

1. 按 `samples/expected/<名>.txt` 与同名 `samples/images/<名>.ppm` 一一对应，文件里的 key=value
   逐行核对：`colors_limit` 是本次调用的上限，`mean_abs_error_max` 与 `max_pixel_error_max` 是
   上限，误差用第二节公式从输出目录独立重算，允许 0.001 的显示误差；`colors_used` 必须等于
   索引图里实际出现的索引个数。
2. 确定性：同一输入连跑两次，`palette.txt` 与 `indices.pgm` 逐字节一致，`report.json` 解析后除
   `elapsed_ms` 外逐字段相同，页面除 `data-metric="elapsed_ms"` 那个节点外内容一致。不许写
   时间戳、绝对路径、主机名，也不许让结果依赖随机初值或集合遍历顺序。
3. 格式：第四节的三份输出齐全；`palette.txt` 有序、无空行；`indices.pgm` 的索引都小于
   `colors_used`；每个调色板条目都被用到。
4. 环境：只用标准库，不联网，无构建步骤，`python -m unittest` 能跑通，测试只读 `samples/`。

## 六、样例说明

| 素材 | 尺寸 / 像素 | 覆盖 | 颜色上限 |
| --- | --- | --- | --- |
| `flat.ppm` | 320×240 / 76,800 | 大片纯色：整图只有 6 种颜色，必须无损 | 8 |
| `fewcolors.ppm` | 256×192 / 49,152 | 只有少数几种颜色的海报式插画，共 30 种颜色 | 16 |
| `gradient.ppm` | 320×240 / 76,800 | 平滑渐变：均匀取色在这一张会明显超标 | 32 |
| `noise.ppm` | 512×384 / 196,608 | 细碎噪声：几乎每个像素都是新颜色 | 64 |
| `mixed.ppm` | 1920×1080 / 2,073,600 | 渐变、大片纯色、颗粒、平滑纹理拼一张，性能与内存量它 | 256 |

`samples/expected/*.txt` 与 `samples/images/*.ppm` 同名成套，逐行给出上限；`samples/notes.md`
是现场记录。
